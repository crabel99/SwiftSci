# Milestone 5: public datasets

Milestone 5 adds H2O-derived grouping and one pinned real-data workflow to the existing standardized contracts. The 27 NIST univariate reference cases remain intact. This does not certify the entire numerical library. Kiraa stays an unofficial experimental reference with known bugs, outside certification and the supported production comparison engines.

## Implementation

Five queries follow the pinned H2O grouping semantics, using separately sampled string and integer key domains. Each runs with broadly uniform keys and an 80 percent forced hot key. These are independently generated finite, non-null data, with sizes and distributions documented as different from the official benchmark. Tiny inputs contain 257 rows; the production profile contains 100,000 rows. No upstream H2O script was copied.

The UCI red-wine fixture is pinned by original and derived hashes and attributed under CC BY 4.0. The pipeline reads all 1,599 rows, selects quality >= 6, stably sorts by alcohol, fits population scaling on 11 features and exports IDs, targets and the feature matrix. Its 855 output rows are checked against a 50-digit Decimal reference. Target-based selection is a descriptive preprocessing benchmark, not a model-evaluation practice.

The contribution adds public manifests, fixtures, query definitions, adapters, negative tests and CI coverage. No production Sources files or Package settings changed. Internal decisions and this report belong only on engineering-notes.

All five run certificates passed audit. Total: 242 fresh processes and 506 measured samples, with no unresolved timings. The largest absolute discrepancy in the new profiles was 5.73e-14. Existing NIST checks retain their dataset-specific tolerances, so error magnitudes across different profiles are not a common accuracy score.

The contract suite increased from 46 passing tests to 54. The final eight additions cover hand-calculated grouped answers, pinning, distributions, workload compatibility, full wine output, row alignment, corrupted data and invalid provenance fields. A checksum-valid wrong expected row ID caused both real workers to exit 1 with failed responses and no accepted samples.

The Release worker built successfully and passed the actual binary check for absent LLVM coverage instrumentation. The previous milestone's full native Debug/Release suites were not rerun because no production code changed. The real Release operations and existing numerical conformance cases ran here. Hosted CI has not run because the contribution commits remain local.
