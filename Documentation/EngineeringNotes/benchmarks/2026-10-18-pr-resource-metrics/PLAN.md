# PR resource qualification, first matched study

Frozen before measurement on 2026-10-18. Recompile exact introduced-source parent/merge pairs for PRs 39, 45, 70, and 82 with one installed Swift compiler, macOS 14 deployment target, Release whole-module optimization, and identical pinned dependency objects within each pair. Dependency objects are fingerprinted. This is a supplemental controlled source comparison, not a historical package rebuild or a claim about the complete latest main.

CPU backend throughout, native thread scheduling without thread overrides. AC power required. Hold input bytes, schema inference, dimensions, selection order, precision, output ownership, validation, and compiler flags equal. No production changes. No timing during builds or other benchmarks. Natural existing desktop activity remains allowed and recorded.

Metrics per operation: process user+system CPU delta across all threads, wall time, live malloc bytes before and while owning the result, post-release live malloc, and process peak RSS before output validation. CPU/wall include API execution and result release but exclude independent complete-output validation. No energy or active hardware-core attribution. Live malloc excludes non-malloc allocations. RSS includes setup and allocator history. Memory probes are separate fresh processes with one operation and no warmup; repeated timing has two warmups and seven samples.

Five paired process rounds rotate before/after order. Three independent memory pairs per case. Preserve all samples and observed paired ranges. Every output must match independent exact fixture values. A mismatch blocks that case; no tolerance changes. The MLP study uses the same deterministic trained weights and a separately calculated prediction oracle with a declared bound before timing.

Dataframe cases: PR39 CSV inference at 100k/1M rows x4 columns, quoted 1M x4, gather 100k/1M x4 and 100k x32. PR45 target 100k/1M x8, flat matrix 100k x8 and 8192 x128. PR82 compact select-plus-matrix at 16384x128,512x2048,4096x8. Values are deterministic exactly representable Doubles; row selection reverses the two-thirds of rows not divisible by three. CSV schema inference is performed by both versions, with identical file bytes. File cache is warm; filesystem cold-read performance is excluded.

Classify CPU and memory separately. A reduction in both supports a resource-efficiency improvement for that measured workload; a gain in only one is a tradeoff. No weighted aggregate score. No automatic policy adjustment or acceptance threshold tuned to these results. The current study establishes representative per-PR costs, not full application throughput under memory pressure or GPU/NPU efficiency.

MLP cases, declared before measurement: one, 32, 256, and 4096 rows with 32 features; 256 and 4096 rows with 128 features. Two ReLU hidden layers have width P and P/2. Both versions fit the same eight training rows for one iteration with seed 42, outside prediction timing. Check identical trained-weight and oracle fingerprints between versions. Check every prediction against a separately accumulated scalar forward pass using abs(error) <= 1e-10 * max(1, abs(reference)). Prediction, output allocation, actor dispatch, and output release are timed; fitting, source creation, and validation are not. This is the existing row-input prediction API, not an end-to-end CSV/training workflow. Exact SwiftML source is rebuilt; all dependent module/object bytes are held equal within the pair. Those fixed dependencies need not match the historical package resolver state, so results qualify this controlled source comparison only.
