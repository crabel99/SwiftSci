# Representative Core ML workflow

SwiftSci already has the execution and complete-workflow measurement pieces. The remaining roadmap work is current, reproducible representative-model evidence with independent accuracy, explicit timing boundaries and observed device attribution. Reuse the existing workflow controller.

Offline, `trained.py` verifies repository WDBC/wine fixtures and disjoint splits, fits StandardScaler and a 64×64 ReLU MLP on training rows, rounds weights once to Float32, and checks an independent NumPy forward pass against scikit-learn at `1e-12`. It saves weights, scaling, row IDs, warnings and held-out scores. Classification scores apply sigmoid to returned logits; wine scores undo training-only target scaling. These are Python-trained models and development benchmarks, with no established application acceptance threshold.

At inference, callers compile a model artifact and select names and allowed compute units. `CoreMLPredictor` loads a compiled artifact, checks features/shape, admits estimated request memory, packs inputs, executes Core ML and copies results into owned Double columns with row provenance. Its ordinary public route is synchronous. `CoreMLMatrixPool.withPool` instead retains one model and exclusive input/output buffers per slot. Its immutable `inputPreparation()` contract applies a training-fitted `StandardPreprocessingPlan` directly into reserved model-typed storage. Prediction copies those prepared bytes into a slot, awaits native async inference and extracts owned outputs. Scope closure drains work before releasing reservations. Bounded pipeline and retained-session APIs already compose this flow.

The existing `FusedCoreMLWorkflow.swift` and `FusedPreprocessingTrial/run_coreml.py` already exercise raw held-out batches through production preprocessing, preparation, pool inference, owned outputs and input-reservation cleanup. `native` stages imputation/scaling; `native-owned` consumes unique input; `fused-direct` calls the supported fitted preparation API. Package-only packed modes supply comparison controls. Interleaved measurements compare exact outputs and row identities against the native path, sample RSS/thermal state and require all owners/reservations to drain.

Its wall timer starts after raw JSON decoding, source `PreparedNumericBatch` construction, row selection and unique-input copying. Training-plan fitting, model compilation/load and preflight are also excluded. It measures the complete in-memory raw-batch-to-owned-output workflow. Source construction and deployment are separate scopes. Raw JSON decoding does not need to be included in an inference total. The worker currently requires Covertype's exact 11340 training rows, 8192 held-out rows, selected IDs in `[15120,581012)`, and 1024/8192-row requests. The controller fixes `fixture-512-{rows}.json` and `program16.mlpackage`. It cannot accept WDBC/wine unchanged.

Use WDBC/wine first because their verified source data exists and no complete historical trained-model cache was recovered. The smallest representative-inference contribution can execute existing `trained.py`, retain its frozen artifacts and quality evidence, and record/inspect an actual trace of the same model and public adapter. Measure conversion separately, retain current load/first/warm records, and describe excluded phases accurately. This needs no new workflow mechanism.

SwiftSci's public MLP exporter emits rank-one examples; a standalone fixed matrix artifact can use the existing fixture builder's same frozen weights, matching the current trained.py direct/public matrix comparison. No new production interface is needed.

Its current worker/native equality proves transport equivalence, not independent model accuracy. Compare all outputs against the frozen NumPy reference with unchanged strict Double tolerances and report held-out task quality, including precision failures. Validate global held-out IDs through the raw fixture's selection mapping. Logical copy bytes and reservations do not prove physical-memory bounds or zero-copy execution.
