# Prepared PCA grounding

Read-only source review at upstream `e19db7dda4567c425b7eb002da82e234e6c7980f`. All paths below are relative to `/private/tmp/swiftsci-prepared-pca-20261026/source`. This describes current behavior and reusable mechanisms; it does not choose new defaults. No tests were executed by this grounding pass.

## Overview

PCA is a stateful actor in SwiftCluster. Its public fit, transform and fitTransform APIs currently accept nested Double rows only. Fitting picks a hardware backend, then selects the CPU full or randomized solver when routed to CPU. Every transform uses CPU Double accumulation against the exported fitted state, including models fitted through the GPU route.

The existing prepared foundation owns Double columns plus separate validity bits. It already packs either matrix layout and composes row provenance through selections. The PCA integration can use that storage directly without adding a new ownership or selection model. PCA is asynchronous and changes feature count, while PreprocessingTransformer is synchronous and its generic prepared adapter preserves feature count. Existing Pipeline conformance is therefore not a ready-made PCA integration point.

## Current execution and arithmetic

- `Sources/SwiftCluster/Core/PCA.swift:74-101`: constructors require positive nComponents. The default constructor sets solver `.auto`; the other preserves an explicit solver. Device defaults to `.auto`.
- `PCA.swift:106-139`: fit rejects empty outer/first rows and k exceeding min(samples, features), awaits HardwareRouter, stores resolvedDevice, then runs CPU or MLX fitting. There is no common rectangular, finite-value, dimension-capacity, or checked-product validation before routing.
- `Sources/SwiftPreprocessing/Core/HardwareRouter.swift:25-36`: explicit CPU/GPU remain explicit; ANE becomes GPU. PCA `.auto` is CPU only when samples < 2,000 AND features < 500. This routing rule is independent of solver choice.
- `PCA.swift:143-161`: CPU `.auto` means randomized iff Double(k) < 0.8 * Double(min(samples,features)). `.full` and `.randomized` are exact overrides. GPU ignores the CPU solver setting.
- `PCA.swift:279-367`: full CPU computes each feature's Double sum in row order, divides by sample count, then allocates an M*N centered column-major Double array. It queries and executes LAPACK dgesdd with thin vectors, allocating singular values, M*minDim U, minDim*N Vt, integer workspace, and Double workspace. Both dgesdd statuses are checked. Vt's first k rows become nested Double components and get Vt-based sign normalization. Selected variance is s[k]^2 / max(1,M-1); total variance uses ALL singular values, not only retained k.
- `PCA.swift:164-203`: randomized CPU computes the same per-column row-order sums, scales means with vDSP by reciprocal sample count, copies the nested X into Xc and mutates every entry to center. RandomizedSVD then packs Xc again. Selected variance uses s[k]^2 / max(1,M-1). Total variance is the centered Frobenius squared norm divided by max(1,M-1), reduced row-first then feature-first, preserving omitted component variance.
- `Sources/SwiftCluster/Decomposition/RandomizedSVD.swift:79-225`: public compute validates empty first dimensions and rank only; it does not check rectangular rows, negative p/q, dimension overflow/capacity, or LAPACK statuses. It allocates A in column-major order, draws the deterministic sketch with defaults p=10, q=2, seed=42, and l=min(k+p,min(M,N)). BLAS computes Y=A*Omega, then each power pass computes Z=A^T*Y and Y=A*Z without intermediate orthonormalization. Thin QR overwrites Y, then B=Q^T*A receives a small dgesdd. It computes Ufull=Q*smallU even though PCA consumes only S/Vt, materializes nested U and Vt, copies top singular values, and sign-flips U/Vt together. Those public U results are live API behavior and are not dead code.
- `PCA.swift:371-415`: GPU route flattens nested Double input to row-major Float, creates MLXArray, computes MLX feature mean and centering, then explicitly calls `svd(XCent, stream: .cpu)` within the surrounding GPU default-device scope. Keep this distinction: resolvedDevice is GPU, but SVD explicitly uses the CPU stream. Mean and singular values are evaluated/exported as Float then widened to Double; Vt is exported as Float then widened into k nested Double rows. It uses the same Vt sign normalization and Double variance formula from Float singular values.
- `PCA.swift:422-459`: transform checks fitted state first, then nonempty rows, then every row width against fitted mean count. For each row, k, c it computes `sum += (row[c] - mean[c]) * components[k][c]` in Double with c ascending. It allocates one k-element row per input row. fitTransform calls fit then this ordinary transform; it does not use U*S.
- `PCA.swift:67-72`: ratios are selected variances / total input variance, or zero for total variance <= 0. Unfitted ratios are nil. No separate singular-value public state exists.

## Prepared storage, layout, validity and provenance

- `Sources/SwiftDataFrame/Core/PreparedNumericBatch.swift:4-24`: batches retain feature names, row count, CompactNumericColumns and optional sourceRows. nil sourceRows means identity, avoiding identity storage. Initializers enforce column lengths and matching metadata. Public dense initialization at 100-109 allows duplicate names and valid NaNs. Do not infer uniqueness from this type.
- `PreparedNumericBatch.swift:142-171,208-211`: CompactNumericColumn owns [Double], optional UInt64 validity bitmap, and nullCount. Missing slots contain numeric NaN plus a false bit; valid NaN has a true bit. `columns` and its values are package-visible and reusable inside SwiftCluster. Snapshots use Array copy-on-write.
- `Sources/SwiftDataFrame/Core/DataFrame+Matrix.swift:50-52,110-123,168-174`: dataframe preparation selects requested names in supplied order, including duplicates. It supports Double, Int64 and Bool. Compact Double columns share their buffers; optional Double, Int64 and Bool become compact Double storage. Missing-name errors have precedence over unsupported-type errors. Int64 conversion follows ordinary Double precision.
- `PreparedNumericBatch.swift:44-50`: selectingRows validates all positions before output allocation, retains order and duplicates, gathers columns, and composes sourceRows through prior selections. Public originalRowIndices allocates identity indices only when requested. `originalRowIndex(at:)` avoids that identity array for internal indexed access.
- `Sources/SwiftDataFrame/Core/CompactNumericColumn+Gather.swift:3-54`: gather allocates selected values and copies validity to destination positions, counting missing outputs including repetitions. Small selections use one bitmap word. `PreparedNumericBatch+Gather.swift:5-21` dispatches columns concurrently only for >=2 columns, >=1,024 selected rows and >=2MiB values; <=8 workers write disjoint column slots and join before return.
- `PreparedNumericBatch.swift:55-95`: matrix packs Double values in row or column major order, checks element-count overflow and can reject missing values through nullCount. `.reject` still permits valid NaN. One-column matrices share the source value buffer; multi-column column-major output appends contiguous columns; row-major output uses direct or 16KiB tiled writes. Source names and provenance carry into PreparedNumericMatrix.
- `PreparedNumericBatch.swift:228-255`: PreparedNumericMatrix owns public-read/private-set values, order, names, row count and provenance. Package `withMutableValues` supplies a scoped mutable buffer, triggering COW when shared. Public subscripting supports both layouts.
- `PreparedNumericBatch.swift:128-129`: `replacingNumericColumns(_:columnNames:)` constructs a numeric batch retaining rowCount and sourceRows. Supplied names can change output feature count. This is the existing helper for PCA score columns with preserved original row mapping. By contrast `replacingRows` at 273-277 explicitly requires original feature count and names; it is unsuitable for dimension reduction.
- `PreparedNumericBatch.swift:267-270`: package requireFinite checks both missing and nonfinite data, but its message says "Regression input". It is regression-specific wording, not a general PCA error policy.
- `Sources/SwiftPreprocessing/Core/PreparedFloatPacking.swift:5-27` and `ScopedGPURead.swift:41-75`: existing package tools convert prepared columns directly to row-major Float into an owned shared Metal buffer without nested rows. ScopedGPURead validates extents, keeps Metal/MLX ownership alive, synchronizes GPU before leaving the closure, and uses a raw pointer only for whole-page alignment/extents; otherwise MLXArray copies the supplied buffer. All lazy MLX results must be evaluated/exported before the closure returns. Reusing it must retain current PCA Float/MLX mean/SVD arithmetic.
- `Sources/SwiftML/Core/LinearRegression.swift:154-162,496-511`: existing precedent records exact prepared feature-name order on fit and compares it for prepared predict; legacy fit clears that schema. This is precedent, not current PCA behavior. PCA currently stores no names.

## Dataframe glue and composition constraints

`Sources/SwiftCluster/Core/DataFrame+Cluster.swift:5-18,47-54` uses a private shared extractFeatures helper. It accepts Double typed columns only, materializes all nested rows, converts nil to 0, preserves supplied column order and duplicate names, then constructs default PCA and fits. Empty frames return [] before validating requested names. KMeans, DBSCAN and clustering metrics still use the helper, so it is not dead when replacing only the PCA call site. A new prepared path must not silently equate this legacy nil-to-zero behavior with prepared missing-to-NaN extraction.

`Sources/SwiftPreprocessing/Core/PreprocessingTransformer.swift:5-28,44-60` requires synchronous mutating fit and synchronous transform and uses a feature-preserving prepared fallback. `Pipeline.swift:54-88` uses native prepared overloads only when every step opts in; otherwise it converts all rows once and requires the final prepared shape to match. PCA actor APIs cannot simply conform to that protocol while retaining actor/async semantics.

## Subtract first

Repository-wide references establish three truly dead private definitions: `PCA.swift:14-31` dgesvd_wrapper, `PCA.swift:205-277` fitCPUCov, and `RandomizedSVD.swift:7-33` dgemm_rsvd. Other modules have their own same-named dgesvd wrapper; the private PCA wrapper is separate and uncalled. Remove these before building shared execution. Full-SVD U allocation is currently required by its chosen dgesdd job mode; public RandomizedSVD U output and PCA.svdFlip forwarding are used API, not removable dead code. Shared extractFeatures remains live for non-PCA glue.
