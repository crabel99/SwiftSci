# CSV date conversion source comparison

Source review dated 2026-10-21. No production code changed and no timing experiment ran for this note.

SwiftSci should first make a cache miss inexpensive for declared numeric date formats. Converted-value reuse is a separate optimization. DuckDB's measured CSV path parses every non-null timestamp from bytes with a prepared format and writes directly into a typed vector. Polars combines a byte parser with a bounded result cache. pandas combines a native array conversion with an optional whole-column unique-value cache. Those mechanisms support a broader investigation than caching the preceding UCI date. They do not establish how much of SwiftSci's measured CPU or RSS any proposed change would remove. The source evidence follows below.

## pandas

The C wrapper marks date columns as non-converted during token ingestion, reads native chunks under the default low-memory path, concatenates them, then applies date conversion. `date_converter` obtains a string array and calls `to_datetime` with the requested format and cache flag. Date conversion therefore happens after CSV tokenization; the measured path is not Arrow CSV or a Python callback for each row. [C wrapper](https://github.com/pandas-dev/pandas/blob/2905718b126579d2cf0fe5bae05bd75facb67d77/pandas/io/parsers/c_parser_wrapper.py#L183-L201), [chunk assembly and conversion](https://github.com/pandas-dev/pandas/blob/2905718b126579d2cf0fe5bae05bd75facb67d77/pandas/io/parsers/c_parser_wrapper.py#L238-L347), [date dispatch](https://github.com/pandas-dev/pandas/blob/2905718b126579d2cf0fe5bae05bd75facb67d77/pandas/io/parsers/base_parser.py#L763-L795).

The converted-value cache has an explicit heuristic. Arrays of at most 50 elements bypass it. Up to 5,000 elements, pandas samples the first tenth; larger arrays sample the first 500. More than 70% unique values in that prefix disables caching. Otherwise it computes all unique values, converts those, and maps results back to the complete column. This is a column-sized dictionary of unique dates with no fixed entry cap in this path, not a last-value cache. Prefix order can change the decision. Shuffling the same date multiset can therefore change pandas' conversion strategy even though total cardinality stays fixed. [Heuristic and unique conversion](https://github.com/pandas-dev/pandas/blob/2905718b126579d2cf0fe5bae05bd75facb67d77/pandas/core/tools/datetimes.py#L156-L263), [mapping back](https://github.com/pandas-dev/pandas/blob/2905718b126579d2cf0fe5bae05bd75facb67d77/pandas/core/tools/datetimes.py#L297-L318).

Format reuse is different from result reuse. The non-ISO `%d/%m/%Y` path obtains a compiled regular expression once for `array_strptime`; its loop matches each input, extracts directive groups, validates the calendar conversion, and writes into a contiguous 64-bit datetime array. The format-regex cache declares a maximum of five and clears when its size exceeds that threshold. It does not cache converted dates. This is Cython orchestration with Python regex objects and group dictionaries, so calling the entire path a SIMD byte parser would be wrong. Nulls become the `NaT` integer sentinel. [Regex preparation](https://github.com/pandas-dev/pandas/blob/2905718b126579d2cf0fe5bae05bd75facb67d77/pandas/_libs/tslibs/strptime.pyx#L218-L244), [array loop and storage](https://github.com/pandas-dev/pandas/blob/2905718b126579d2cf0fe5bae05bd75facb67d77/pandas/_libs/tslibs/strptime.pyx#L389-L415), [format matching](https://github.com/pandas-dev/pandas/blob/2905718b126579d2cf0fe5bae05bd75facb67d77/pandas/_libs/tslibs/strptime.pyx#L594-L705), [cache limit](https://github.com/pandas-dev/pandas/blob/2905718b126579d2cf0fe5bae05bd75facb67d77/pandas/_libs/tslibs/strptime.pyx#L877-L881).

CSV string conversion also maintains a temporary hash table that reuses decoded Python strings within the conversion chunk. Null tokens are checked before decoding. Numeric conversion writes native arrays and selects the requested round-trip floating-point converter. The C parser releases the GIL around some tokenization and numeric work, but these source loops do not dispatch parallel CSV workers. GIL release alone is not multithreading. Chunked token buffers also do not mean bounded total memory for an eager result: converted chunks and the final arrays still require storage. [String reuse](https://github.com/pandas-dev/pandas/blob/2905718b126579d2cf0fe5bae05bd75facb67d77/pandas/_libs/parsers.pyx#L1485-L1540), [floating-point selection](https://github.com/pandas-dev/pandas/blob/2905718b126579d2cf0fe5bae05bd75facb67d77/pandas/_libs/parsers.pyx#L506-L512), [chunk loop and tokenizer](https://github.com/pandas-dev/pandas/blob/2905718b126579d2cf0fe5bae05bd75facb67d77/pandas/_libs/parsers.pyx#L816-L910).

## Polars

The measured API first builds an eager string column. Exact datetime conversion then uses `as_datetime`. With this format and no timezone, it selects the fast Rust parser. `compile_fmt` validates combinations and expands aliases such as `%F`; it does not compile `%d/%m/%Y` into machine code or a predecoded instruction sequence. The parser still walks the format bytes on a cache miss, reads numeric fields with `atoi_simd`, checks literal separators and full consumption, and validates the date through Chrono. A failed fast parse falls back to the Chrono transformation. This makes the miss path useful for distinct dates too. [Exact dispatch and strict check](https://github.com/pola-rs/polars/blob/1bd8ec12f42d40fcec62badf32ef2177d2377d8d/crates/polars-expr/src/dispatch/strings.rs#L490-L541), [datetime conversion](https://github.com/pola-rs/polars/blob/1bd8ec12f42d40fcec62badf32ef2177d2377d8d/crates/polars-time/src/chunkedarray/string/mod.rs#L258-L337), [format preparation and parser](https://github.com/pola-rs/polars/blob/1bd8ec12f42d40fcec62badf32ef2177d2377d8d/crates/polars-time/src/chunkedarray/string/strptime.rs#L17-L215).

Result caching activates when requested and the column length exceeds 50. Capacity is `floor(sqrt(column_length))`, with no pandas-style uniqueness sample in this path. The LRU implementation uses a hash table, slot storage, and recency links; it evicts the least recently used entry when full. It caches conversion results, including failed parse results. Null inputs bypass conversion. The UCI column therefore gets capacity 1,440 for 1,442 unique dates. Contiguous runs make the two-entry shortfall unimportant. Shuffled values near this capacity exercise a different behavior, and substantially larger cardinalities exercise eviction. A last-value cache would lose much more reuse after shuffling. These are consequences of the algorithms, not measurements from this review. [Cache selection](https://github.com/pola-rs/polars/blob/1bd8ec12f42d40fcec62badf32ef2177d2377d8d/crates/polars-time/src/chunkedarray/string/mod.rs#L270-L322), [LRU implementation](https://github.com/pola-rs/polars/blob/1bd8ec12f42d40fcec62badf32ef2177d2377d8d/crates/polars-utils/src/cache.rs#L10-L226).

The eager CSV reader identifies byte chunks and launches field parsing through Rayon. Typed builders append numeric values or nulls; string builders use Arrow binary views. Primitive builders use Arrow mutable primitive arrays. Date conversion produces integer timestamps with nullable array storage rather than one Foundation date conversion per output row. The temporal function itself uses an elementwise traversal with a local cache; its source does not justify assuming that this one date column is parsed across the full Rayon pool. CSV parallelism and temporal-expression parallelism must be measured separately. [CSV chunk tasks](https://github.com/pola-rs/polars/blob/1bd8ec12f42d40fcec62badf32ef2177d2377d8d/crates/polars-io/src/csv/read/read_impl.rs#L353-L455), [field null checks](https://github.com/pola-rs/polars/blob/1bd8ec12f42d40fcec62badf32ef2177d2377d8d/crates/polars-io/src/csv/read/parser.rs#L1140-L1166), [CSV builders](https://github.com/pola-rs/polars/blob/1bd8ec12f42d40fcec62badf32ef2177d2377d8d/crates/polars-io/src/csv/read/builder.rs#L127-L190), [primitive builder](https://github.com/pola-rs/polars/blob/1bd8ec12f42d40fcec62badf32ef2177d2377d8d/crates/polars-core/src/chunked_array/builder/primitive.rs#L1-L51), [value buffer and validity bitmap](https://github.com/pola-rs/polars/blob/1bd8ec12f42d40fcec62badf32ef2177d2377d8d/crates/polars-arrow/src/array/primitive/mod.rs#L56-L60).

`try_parse_dates` during CSV ingestion and lazy `scan_csv` are different options. Neither explains the measured operation, which explicitly reads Date as String and converts it afterward. A fast direct CSV date path elsewhere in the library must not be substituted for this traced path.

## DuckDB

Setting the timestamp format parses it into a `StrpTimeFormat` containing directive/literal state. The scanner copies that prepared format into its result state. For the measured TIMESTAMP type, each non-null field reaches `TryParseTimestamp(char*, length, timestamp_t&)` and writes directly to the output vector slot. The format parser loops over prepared literals and numeric directives, accumulates decimal digits, and converts validated calendar fields into a timestamp. It does not require a Python datetime object or per-field Foundation formatter call. [Format preparation](https://github.com/duckdb/duckdb/blob/069cc9f9b5be802405797faecc284961b07c70ef/src/execution/operator/csv_scanner/util/csv_reader_options.cpp#L214-L230), [scanner setup](https://github.com/duckdb/duckdb/blob/069cc9f9b5be802405797faecc284961b07c70ef/src/execution/operator/csv_scanner/scanner/string_value_scanner.cpp#L103-L122), [typed timestamp conversion](https://github.com/duckdb/duckdb/blob/069cc9f9b5be802405797faecc284961b07c70ef/src/execution/operator/csv_scanner/scanner/string_value_scanner.cpp#L374-L389), [prepared-format parser](https://github.com/duckdb/duckdb/blob/069cc9f9b5be802405797faecc284961b07c70ef/src/function/scalar/strftime_format.cpp#L886-L955), [timestamp conversion](https://github.com/duckdb/duckdb/blob/069cc9f9b5be802405797faecc284961b07c70ef/src/function/scalar/strftime_format.cpp#L1597-L1612).

No converted-date lookup or repeated-value cache appears along this direct scanner-to-format-parser call path. That is a scoped source finding, not a claim that DuckDB never caches anything. Its measured performance therefore cannot be explained solely by memoizing the 1,442 UCI dates. Prepared format reuse, byte parsing, typed output, and scanner organization remain relevant when dates are unique.

The scanner initializes typed chunks and obtains separate data and validity pointers. It compares configured null strings before conversion and marks invalid slots in the validity mask. The global CSV state supplies separate file boundaries to scanners, and maximum concurrency depends on file size and bytes per thread. This is row-region concurrency, unlike assigning one entire date column to one worker. The resulting eager table and included Arrow export still consume memory; this source review does not establish zero-copy export or a bounded overall process footprint. [Null handling](https://github.com/duckdb/duckdb/blob/069cc9f9b5be802405797faecc284961b07c70ef/src/execution/operator/csv_scanner/scanner/string_value_scanner.cpp#L264-L299), [scanner boundaries](https://github.com/duckdb/duckdb/blob/069cc9f9b5be802405797faecc284961b07c70ef/src/execution/operator/csv_scanner/table_function/global_csv_state.cpp#L13-L80), [thread limit](https://github.com/duckdb/duckdb/blob/069cc9f9b5be802405797faecc284961b07c70ef/src/execution/operator/csv_scanner/table_function/csv_multi_file_info.cpp#L248-L262).

## What the SwiftSci source establishes

At `a5f6e78a751365ec360efdd4ae8f028db04b441b:Sources/SwiftDataFrame/IO/CSVReader.swift`, lines 24-70 map the file, build the complete record index, then dispatch columns concurrently. Lines 195-205 create one DateFormatter for the date column with POSIX locale, Gregorian calendar, UTC, and leniency disabled. Lines 288-302 construct a String for each date field, check nulls, and call that reusable formatter. The formatter itself is already reused; converted results are not. The date column loop is serial even while other columns run concurrently. [Measured source checkout](</private/tmp/swiftsci-csv-date-format-20261021/Sources/SwiftDataFrame/IO/CSVReader.swift:195>)

The String parser trims field boundaries, and date cleanup trims again and handles surrounding quotes before conversion. These are candidate allocations and scans to profile, not measured percentages. Numeric fields already have byte parsers, so replacing the whole CSV reader is not supported by the date evidence. The default month-first `Date.parse` behavior is intentional and must remain outside an explicit-format optimization unless the contract changes. [Measured String parser](</private/tmp/swiftsci-csv-date-format-20261021/Sources/SwiftDataFrame/IO/VectorizedByteParsers.swift:159>), [date-format contract and evidence](../benchmarks/2026-10-21-csv-date-format/README.md).

The large unquoted path retains a complete flat field index before conversion. Its two-Int field records occupy 16 bytes each on this target, plus 8-byte row starts. For 2,075,260 rows including the header and nine fields, the field payload alone is 284.994 MiB; row starts add about 15.833 MiB. Those are logical temporary payload estimates, excluding capacity and allocator overhead. They are not measured retained RSS after the read. `CSVColumnBuilder<T>` separately stores `[T?]`, and `TypedColumn` exposes those values publicly. The local Swift 6.4 layout probe reports 16-byte strides for both `Double?` and `Date?`. A packed 8-byte value array with a separate validity bitmap has a different cost, but changing this public storage requires its own compatibility and lifetime investigation. [Measured index source](</private/tmp/swiftsci-csv-date-format-20261021/Sources/SwiftDataFrame/IO/SystemsCSVParser.swift:54>), [builder](</private/tmp/swiftsci-csv-date-format-20261021/Sources/SwiftDataFrame/IO/CSVColumnBuilder.swift:1>), [column representation](</private/tmp/swiftsci-csv-date-format-20261021/Sources/SwiftDataFrame/Columns/TypedColumn.swift:1>).

A newer Foundation parsing API is not evidence of a cheaper inner loop. In the reviewed swift-foundation commit `c8cc07611347b283e0acc8a0da03738a42db9ef0`, Date.ParseStrategy obtains a cached ICU formatter, while ICUDateFormatter's parse method clones a calendar, builds UTF-16 storage, and invokes ICU calendar parsing per call. This is an alternative implementation inspected at a pinned source revision. It is not proof of the internals of the installed macOS DateFormatter binary. Profile the actual Darwin process before assigning cost to ICU, calendar cloning, bridging, or temporary objects. [Date.ParseStrategy source](https://github.com/swiftlang/swift-foundation/blob/c8cc07611347b283e0acc8a0da03738a42db9ef0/Sources/FoundationInternationalization/Formatting/Date/DateParseStrategy.swift#L61-L89), [ICU formatter source](https://github.com/swiftlang/swift-foundation/blob/c8cc07611347b283e0acc8a0da03738a42db9ef0/Sources/FoundationInternationalization/Formatting/Date/ICUDateFormatter.swift#L122-L148).

## Semantics and next evidence

The successful corpus matches values, not all error policies. pandas' CSV date wrapper catches conversion failure and can return strings. Polars strict conversion rejects newly introduced nulls. SwiftSci appends nil when explicit conversion fails. DuckDB reports failed typed conversions through its scanner error handling. Any invalid-input comparison must choose a common contract or report those differences separately. Zero nulls on valid data cannot prove equivalent malformed-date behavior. [pandas fallback](https://github.com/pandas-dev/pandas/blob/2905718b126579d2cf0fe5bae05bd75facb67d77/pandas/io/parsers/base_parser.py#L776-L787), [Polars strict check](https://github.com/pola-rs/polars/blob/1bd8ec12f42d40fcec62badf32ef2177d2377d8d/crates/polars-expr/src/dispatch/strings.rs#L537-L539), [DuckDB typed conversion and failure handling](https://github.com/duckdb/duckdb/blob/069cc9f9b5be802405797faecc284961b07c70ef/src/execution/operator/csv_scanner/scanner/string_value_scanner.cpp#L300-L506).

A local diagnostic using the installed Foundation formatter and the measured POSIX/Gregorian/UTC `d/M/yyyy` settings found that `isLenient=false` does not require exact separators or year width. It accepted `1-2-2007` as 1 February 2007 and `1/2/07` as year 7, while rejecting non-leap `29/2/2007`, `31/2/2007`, and trailing junk. This diagnostic is not a cross-engine equivalence test. A fast path must preserve existing accepted inputs through fallback, or make a grammar change explicit. Silent rejection of these values would be a behavior regression.

The next investigation should compare these independent changes:

1. Parse supported declared numeric formats from field bytes with format preparation outside the row loop, full calendar validation, and an explicit fallback for unsupported formats. Measure with result caching disabled first. This tests useful work on every cache miss.
2. Add bounded converted-value reuse separately. Compare no cache, preceding-value reuse, and a bounded associative cache. Include cache admission and eviction costs. Do not select the policy solely from contiguous UCI runs.
3. Profile whole-file metadata, temporary lifetime, and optional-column storage separately. Consider chunk-local indexes or direct typed append only after identifying their contribution and preserving quoted-field behavior. Date parsing and storage changes should have separate measurements.

Use repeated dates in runs, the same multiset shuffled with recorded seeds, cardinalities below and well above cache capacity, and unique dates over a declared supported range. A unique date-time corpus can cover millions of rows without forcing whole-day dates outside an engine's valid range. Include small files around the 50-row threshold and different prefix distributions for pandas' heuristic. Keep text-only and numeric controls.

Semantic gates should cover single- and double-digit days and months, leap days and century boundaries, invalid dates, null tokens, empty fields, whitespace, trailing garbage, quoted fields, embedded delimiters and newlines, supported year limits, and unsupported format fallback. Add timezones and fractional seconds only under a separately stated contract. Check values, nulls, row order, output types, and error behavior before accepting timing samples.

Measure both process CPU and elapsed time, along with baseline RSS, held-result RSS growth, and peak process RSS. Use fresh workers and the existing preflight/hash discipline. Profile parser calls and allocations separately from acceptance timing. A cache improvement must have bounded memory and acceptable high-cardinality overhead; a parser improvement must help distinct values without semantic drift; an index change must reduce the intended memory measure without unacceptable CPU cost. Configured thread counts do not establish active cores, and these source traces do not predict a recovered speed ratio.
